# 墨集 · 实现缺口与决策缺口梳理

> 目的：在「待办核心」第一批开工前，把**代码实际缺什么**（实现缺口）和**还没拍板什么**（决策缺口）分开列清，避免边写边想。
> 依据：`dida365-features.md`（滴答经验）、`feature-backlog-from-dida365.md`（功能需求）、已锁定的三项架构决策（页内三栏 / 宽屏常驻+窄屏抽屉 / 先待办核心）。
> 代码基线：2026-11-14 实际源码（types / storage / store / Todos / Sidebar / Topbar / App）。

---

## 一、现状基线（代码事实）

- **实体**：Note / Memo / Todo / Event / Tag 五个；Todo 字段仅 `title, description?, priority(high/medium/low), dueDate?, completed, createdAt, completedAt?`。
- **存储**：`version: 1`，sanitize + normalize 迁移机制完备；有 `savedAt` 时间戳、`persistSink` 桌面壳同步、`importState` 全量校验导入。
- **store**：单 Zustand store，`commit()` 统一落盘；`updateTodo` 已存在且维护 `completed ⇔ completedAt` 不变量。
- **Todos 页**：`max-w-3xl` 单栏居中；新建走弹窗；**只有新建 / 删除 / 勾选，没有编辑入口**；筛选（状态/优先级）+ 排序（创建/截止/优先级）。
- **Sidebar**：固定 7 项功能导航，无数据概念。
- **Topbar**：全局搜索（分组 + 键盘导航）+ 新建，已成熟。

## 三、决策缺口（开工前必须拍板）

> 每条给选项与倾向，**未拍板前对应代码不应开工**。

| # | 问题 | 选项 | 倾向 |
|---|---|---|---|
| D1 | 文件夹层一期做吗？ | 两层（文件夹→清单）/ 先只做清单 | **先只做清单**，文件夹等清单数量真的多了再加；数据模型预留 folderId 即可 |
| D2 | 优先级第 4 档怎么加？ | 加 `none` 并改为默认 / 保持 medium 默认 | **加 none 且新建默认 none**（大多数任务无需标级）；旧数据保持原值不动 |
| D3 | abandoned 状态机？ | `status: active/completed/abandoned` 单字段 / completed+abandoned 双布尔 | **单字段 status**（互斥天然成立），需迁移旧 completed 布尔；abandonedAt 记录时间；**不计入周报完成数**，单独统计 |
| D4 | 子任务规则？ | 层级 / 字段 / 级联 | **仅一层**；子任务只有 title+completed，无独立 listId/dueDate/priority；父删则子删（确认对话框说明）；父完成不级联子完成；子任务不进收集箱/今天统计 |
| D5 | Todo 引入 tags 吗？ | 引入 / 不做 | **一期不做**。清单已承担归类，标签等四象限批次再评估 |
| D6 | 描述用什么格式？ | Markdown（复用现有链路）/ 富文本（滴答式） | **Markdown**。与笔记一致、无新依赖；工具条选中时浮现，提供加粗/列表/待办语法按钮 |
| D7 | 智能清单范围？ | 今天/最近7天/收集箱 | **三个足够**；「最近7天」= 未来7天+已逾期；逾期任务在今天视图**独立红色分组**置顶，不另设「逾期」入口 |
| D8 | 视图偏好存哪？ | 独立 localStorage UI 键 / 数据实体 | **独立 UI 键**（如 `moji-ui-prefs`），不进导出数据——偏好是设备级的，数据是内容级的 |
| D9 | 路由要不要 URL 同步？ | `/todos?list=&task=` / 不同步 | **要**，与 `/notes/:id` 先例一致；刷新/分享链接可还原现场；task 选中态用查询参数而非路径 |
| D10 | 手动拖拽排序一期做吗？ | 做 / 不做 | **不做**，保持现有排序（创建/截止/优先级）；数据模型不预留 sortOrder，避免为用不到的字段付迁移成本 |
| D11 | 已完成怎么展示？ | 底部折叠分组（滴答式）/ 沿用筛选 | **底部折叠分组**，替代现有「状态筛选」；筛选只保留优先级 |
| D17 | 清单色板具体色值？ | 设计定稿 | 朱砂/藤黄/青碧/黛蓝/藕荷 + 墨灰，**需要对照 design.md 现有令牌定 hex**，不新造色 |
| D18 | emoji 图标选择器？ | 全量 emoji 库 / 有限集合 / 不做 | **有限集合**（约 30 个常用），全量 emoji 数据体积不值；也可一期只做空白+色点 |
| D20 | 旧筛选工具条去留？ | 全删 / 保留优先级筛选 | **保留优先级筛选**（收进列表头部右侧小控件），状态筛选被 D11 取代，排序保留 |

### 已拍板：笔记编辑器增强（2026-11-14）

- **路线 = 轻量增强（L1+L2），暂不上 TipTap 富文本**。L1：渲染链加 `remark-math` + `rehype-katex` + 高亮/颜色插件，KaTeX 字体**本地打包**（离线约束）、懒加载；L2：源码工具条 + 颜色选择器（向 textarea 插语法）。L3（桌面富文本、MD 双向序列化）后续单独评估。
- **公式语法**：`$行内$` / `$$块级$$` LaTeX，存储为原文，导出/搜索/同步零改动。
- **颜色 = 语义色板 6 色**（朱砂/藤黄/青碧/黛蓝/藕荷/墨灰），与清单色板同源；存储用 HTML 类名（`<mark class="c-vermilion">` / `<span class="c-vermilion">`），**不用自由 hex、不用私有语法**；暗色主题下各色自动调亮度；高亮同时支持 Obsidian 通用的 `==文字==`。
- **与 D6 联动**：若日后上共享编辑器内核，待办描述用精简配置版（去标题、保留加粗/列表/待办/高亮/公式）；当前 D6 维持不变。
- **新增实现缺口**：L1 插件与本地字体接入、L2 工具条组件、颜色语法的 sanitize 白名单（类名只放行 6 色 + `==` 转换）、序列化/渲染纯函数测试（90% 门槛）。

## 四、工作量重估（基于新发现）

此前估算漏了两项隐性工作：

1. **Todos 页编辑能力是从零补**，不是「弹窗改详情」——右键菜单、详情面板、内联添加全是新交互。
2. **现有 Todos 页测试会大面积失效**，G3 不是「补测试」而是「重写测试」。

因此第一批的合理范围建议收敛为：

> **A1–A6 + B1–B5 + C1–C5 + D1–D8 + E1/E2 + G1–G4**，即「数据模型 v2 + 清单 + 三栏 + 详情 + 子任务 + 放弃」，不含标签、拖拽排序、富文本附件。
