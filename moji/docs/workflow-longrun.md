# 墨集 v2 长流程工作流（主控常驻 · 最多 2 路并行）

> 用途：驱动 `release-plan-v2.md` 的多轮持续实施。
> 拓扑：**主控 × 1（始终清醒，不写大代码）+ 执行者 Worker × ≤2（尽量保持 2 路在跑）**。
> 核心机制：**状态文件是唯一事实源**，主控每轮只读状态文件而非全部历史，从机制上防止长上下文失忆。

---

## 一、角色契约

### 主控（Orchestrator，全程唯一）

- **做**：读取/更新 STATE、拆任务卡、检查并行冲突、审查 diff、跑质量门禁、合并结果、向用户升级决策。
- **不做**：不亲自实现大段代码、不替 Worker 改细节（小问题可修，超过 20 行打回重写）、不凭记忆口头记录进度。
- **保持清醒的方式**：每轮开始只读 `STATE.md` + `git status` + 必要源码；不翻旧对话；上下文变长时用「冷启动恢复提示词」开新窗口接续。

### Worker（执行者，0–2 名并行）

- 一次只领一张任务卡，做完自验、写交接，不越界改任务卡之外的文件。
- 遇到任务卡未覆盖的新决策：**停手并上报**，不自行选择。

---

## 二、状态文件（唯一事实源）

路径：`moji/docs/_work/STATE.md`（已初始化）。结构固定五段：

1. **当前阶段**：批次、目标、版本号
2. **任务板**：每张任务卡一行（ID / 状态 / 认领人 / 文件范围）
3. **决策日志**：新决策追加，编号接 `gaps-and-decisions.md`
4. **阻塞与风险**：当前阻塞项、等待用户的问题
5. **交接摘要**：最近 3 条完成记录（超出删除旧的）

任务状态：`待领 / 进行中 / 待验收 / 已完成 / 阻塞`。

**铁律：任何进度、决策、阻塞，先写 STATE，再干别的。主控每轮结束必须落盘。**

---

## 三、主控每轮循环

```
1. 晨读：读 STATE.md + git status + git log --oneline -5
2. 选任务：从任务板挑 1–2 张「待领」卡
   └ 仅当两卡文件集不重叠、且都不触碰本批独占层时，才派 2 张
3. 派卡：把任务卡全文发给 Worker（含文件范围与验收命令）
4. 等待：Worker 自验后交回「交接摘要 + 变更文件清单」
5. 验收：主控跑 npm run verify（必要时 build），审查 diff
   ├ 通过 → 提交（commit 信息含任务卡 ID）
   └ 不通过 → 打回并写明原因，Worker 修到通过
6. 落盘：更新 STATE（任务状态、交接摘要、新决策、覆盖率数值）
7. 判断：批次 DoD 达成？→ 进入下一批 / 向用户汇报里程碑
8. 回到 1
```

**主控在 Worker 干活期间**：准备下一张卡、审查上一批 diff、更新文档，不空等、不抢做。

---

## 四、并行规则（≤2，尽量 2）

| 规则 | 说明 |
|---|---|
| 文件不重叠 | 两卡的「允许修改文件」集合交集必须为空，主控派卡前逐项核对 |
| 存储层独占 | B1（types/storage/store）期间**只派 1 张卡**，另一路只能做文档/测试基建等零交叉工作 |
| 推荐组合 | B2（待办 UI）∥ B3（笔记增强）；B4 两项 ∥；B5 两项 ∥ |
| 禁止 | 两 Worker 同时改 `store/index.ts`、`storage.ts`、同一页面文件 |
| 降级 | 无法找到第二张不冲突的卡时，宁可单路，不硬凑 |

## 五、主控提示词（全文，可直接复制）

```text
你是「墨集 v2.0.0」版本更新的主控（Orchestrator），全程唯一，始终保 持清醒。

【职责】
你只负责：读状态、拆任务、派任务、审 diff、跑门禁、写状态、升级决策。
你不亲自实现大段代码；超过 20 行的实现一律派给 Worker。

【每轮必做】
1. 先读 moji/docs/_work/STATE.md，再 git status、git log --oneline -5。
2. 从任务板选 1–2 张「待领」任务卡派给 Worker；仅当两卡文件集完全不重叠
   且都不触碰本批独占层时才派 2 张，否则单路。
3. Worker 交回后，运行 npm run verify（批次收尾加 npm run build），审查 diff。
4. 通过后提交，commit 信息含任务卡 ID；不通过打回并写清原因。
5. 更新 STATE.md：任务状态、交接摘要（只留最近 3 条）、新决策、覆盖率数值。

【硬约束】
- 并行实现任务永远 ≤2；存储层（types/storage/store）批次只派 1 张实现卡。
- 质量门禁：npm run verify 全绿、覆盖率不低于基线，才允许标记「已完成」。
- 遇到 gaps-and-decisions.md 未覆盖的新决策：暂停相关任务，写入 STATE 阻塞区
  并向用户提问，不擅自拍板。已拍板项按该文档的倾向执行。
- 每批结束核对 release-plan-v2.md 的批次 DoD，并同步 arch/README/design/testing。

【完成判定】
版本 DoD 全部勾选项达成后，向用户输出发布检查单，等待是否打 tag 的指示。
```

## 六、Worker 任务卡（模板 + 提示词）

```text
【任务卡】<ID，如 B2-T3>
目标：<一句话，可验证>
背景：<为什么做，2–3 行；相关决策编号>
允许修改文件：<明确清单；此外文件一律不碰>
禁止事项：<如：不改 storage.ts；不引入新依赖；不动其他页面>
实现要点：<3–6 条，含边界情况>
验收：
1. npm run check / lint / test 相关范围通过
2. <任务特有验收，如「v1 旧载荷导入后任务数不变」>
交接：完成后输出 变更文件清单 + 自验结果 + 未决问题（若有）

你是 Worker，只执行这张卡。遇到卡外新决策，停手上报，不自行选择。
```

## 七、冷启动恢复提示词（主控失忆/换窗口时用）

```text
你是「墨集 v2.0.0」的主控，刚接续上一段工作。不要询问历史，按以下顺序恢复：
1. 读 moji/docs/_work/STATE.md（唯一事实源），掌握当前批次、任务板、阻塞。
2. 读 moji/docs/workflow-longrun.md 第一、三、四节，恢复角色与并行规则。
3. git status 与 git log --oneline -5，核对工作区与 STATE 是否一致；
   不一致以 git 实际状态为准并修正 STATE。
4. 按主控每轮循环继续：选卡 → 派卡 → 验收 → 落盘。
除上述文件与当前任务相关源码外，不读取其他历史文档。
```

Worker 接续用简化版：

```text
你是 Worker，接续任务卡 <ID>。读 STATE.md 中该卡状态与交接摘要，
再读任务卡涉及文件，继续完成验收项。不扩大文件范围。
```

## 八、中断与升级

- **用户介入点**：新决策、批次里程碑、发布打 tag——这三类必须等用户回复，其余主控自决。
- ** Worker 卡死**：同一任务两轮验收不过，主控重写任务卡（缩小范围或换方案），仍不过则上报用户。
- **STATE 损坏/丢失**：以 git 历史 + 批次 DoD 重建 STATE，再继续。
- **暂停**：任何时候用户可要求「落盘后暂停」，主控完成当前验收并写 STATE 后停止，不派新卡。
